# TAPTrack

Nuke tool that runs DeepMind point trackers (BootsTAPNext / TAPNext / BootsTAPIR from `google-deepmind/tapnet`) on a plate and
exports native **Tracker4 / CornerPin2D / Transform**. Artist flow: plug Read → place points (Tracker4 or Roto grid) → Track → Export.
Output nodes work without the tool installed.

## Hard rules
* **No torch/jax inside Nuke.** ML runs in `worker/` (own venv, subprocess). `nuke/` uses only stdlib + `nuke` + `nukescripts`.
* Targets Nuke 16/17 (Python 3.11), Windows + Linux (macOS best-effort CPU). 12 GB VRAM budget: fp16, chunked, never the whole plate in VRAM.
* Weights are never committed (`checkpoints/`, `vendor/` are gitignored). `install/download_weights.py` fetches them; `install/setup_venv.*`
  creates the venv and clones tapnet at the commit in `install/tapnet_commit.txt`.
* Don't invent the tapnet API: `docs/TAPNET_NOTES.md` records what the pinned source does. Trust it over memory.
* Tracker4 export: format is reverse-engineered from `tests/fixtures/tracker4_reference.nk` (the user supplies it); never guess the knob table.

## Layout
`worker/` torch side (CLI `taptrack_worker.py job.json`) · `nuke/taptrack/` Nuke side (`node`, `job`, `export`, `coords`) · `install/` · `tests/` · `docs/`.

## Protocol
`job.json` → worker → `result.json`; progress and errors are one JSON object per stdout line. Queries `[frame, x, y]` in **plate pixels, Nuke
convention** (origin bottom-left, centres at +0.5, the format never the bbox). The worker owns the conversions (`worker/coords.py`, mirrored by
`nuke/taptrack/coords.py`; both tested). Every model is fed a **squashed square** frame (TAPNext 256², TAPIR 512²) — see the notes for why.

## Conventions
* Python 3.11-compatible syntax in `nuke/`; type hints + docstrings; no global state in `nuke/` modules.
* Every artist-facing error = plain-language message + "Details" with the log path. Logs in `~/.taptrack/logs/`.
* Keep `CHANGELOG.md` current.

## Commands
```
.venv/Scripts/python.exe -m pytest                  # coords + GPU accuracy/bidirectional (needs weights)
.venv/Scripts/python.exe -m pytest -m slow -s tests/test_vram.py   # 500 pts x 200 frames VRAM/speed benchmark
```

## Hard-won facts (Phase 2)
* **Never `Popen` the worker directly from Nuke on Windows**: torch's `c10.dll` fails to initialise (WinError 1114) in any child of Nuke 16.1 (GUI and `-t`), while the same command started by another parent works. `job.launch_worker` starts it via WMI (`Win32_Process.Create`) with a `run.cmd`; stdout goes to `progress.log`, exit code to `done.txt`. Cancel = `taskkill /T`.
* **Tracker4 `tracks` cells must be `{curve x<frame> <v> ...}`** (enable: `{curve K ...}`). `setValueAt` output evaluates to 0. Read values with `export.evaluate` (`nuke.expression`), not `getValueAt`. Details in `nuke/taptrack/export.py`.
* **No backslashes in string knobs** (Nuke eats them as escapes on reopen): `job.knob_path`, `node.on_knob_changed`.
* `cmd`: `echo 0>file` redirects handle 0 - write `echo %ERRORLEVEL% > file` with a space.
* `tests/fixtures/tracker4_reference.nk` is generated by `make_tracker4_reference.py` in headless Nuke 16.1 (not recorded from the UI).
* Nuke-side tests: `pytest -m nuke tests/test_nuke.py` (runs `tests/nuke_tests/` in `Nuke -t`); GUI threaded-path smoke: `Nuke16.1.exe tests/fixtures/gui_smoke.py`.
* **Transform conventions (measured, Nuke 16.1):** linear part = `R(rotate) @ [[1,skewX],[0,1]] @ diag(sx,sy)` about `center`, CCW with y up, acting in *desqueezed* space on anamorphic plates (`S^-1 A S`, `S = diag(pa,1)`), `translate` in plate px. Stabilize = same curves + `invert_matrix`. CornerPin2D pairs `to_i` with `from_i` in plate px. `Knob.setValueAt` is fine for ordinary knobs (only the Tracker4 table is special).
* Kling/AI footage is not a rigid-scene reference: see `docs/DRIFT.md`.
* **Button callbacks run inside the TAPTrack Group** (it is the current context): `nuke.nodes.X`, `nuke.selectedNodes()` and `nuke.toNode()` act on the Group's internals. Do node creation / selection in `with g.parent():` and resolve stored full names in `with nuke.root():`. Nuke-side tests must call callbacks inside `with g:` to catch this.
